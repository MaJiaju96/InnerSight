# 项目搭建 · UI 文字设计

需求编号：`feature-20261124154000-项目搭建`　|　S0　|　v0.2　|　2026-11-24　|　「折光」方向已确认，双主题整套稿待终审

依据：已确认的[需求分析书](01-requirements.md)和[项目搭建 PRD](02-prd.md)。本稿设计登录、改密、后台首页、用户管理和角色管理。文中的账号与角色名用于举例；功能状态和权限均以服务端结果为准。

## 1. 打开后台会看到什么

登录前显示「内观 / InnerSight」品牌、认证表单及右上角外观胶囊。登录后，顶栏左侧是中文主标「内观」和英文副标 InnerSight；右上角依次是「浅色／深色」胶囊、当前显示名和账号菜单（修改密码、退出登录）。左侧从上到下是「首页」「用户管理」「角色管理」，主区显示当前页面标题、主要操作和内容。只有后两项都不可用时，导航仅保留首页。没有题库、AI 配置、统计图或待开放入口。

首页标题为「后台首页」。标题下先列「当前账号」与有效角色，再在「可用入口」中列出当前账号可进入的管理页。示例：管理员林青的首页有「用户管理」「角色管理」两个入口；仅有用户读取权限的陈宁只有「用户管理」。无管理权限时写「暂无管理权限。你仍可修改自己的密码。」并提供「修改密码」。无角色账号的角色栏显示「未分配」；仅绑定了停用角色时显示「暂无启用角色」。

| 当前身份或权限 | 管理入口 | 页面上出现的动作 |
|---|---|---|
| 等待首次改密的账号（含管理员） | 仅改密页 | 「修改密码」「退出登录」；不渲染后台导航，直接打开管理页也回到改密页。 |
| 已正常登录，无管理权限 | 无 | 个人首页、修改自己的密码、退出登录。 |
| `user:read` | 用户管理 | 搜索、筛选、翻页、查看；无新增、编辑、授权入口。 |
| `user:manage`（含 `user:read`） | 用户管理 | 新建无角色账号、编辑普通用户显示名、启停普通用户；不显示给自己停用、修改管理员账号、分配角色或重置他人密码的动作。 |
| `role:read` | 角色管理 | 查看角色、绑定人数和固定权限目录；没有新建或修改入口。 |
| 内置管理员 `ADMIN` | 用户管理、角色管理 | 可维护普通用户、他人管理员账号及自定义角色；不能停用自己、移除自己的 `ADMIN`、编辑内置角色。给自己改密始终走个人入口。 |

同一账号可兼具多行权限，按所有启用角色的并集渲染。无权的动作不出现；加载或提交中的动作保留原位置并暂不可用；内置只读等约束用文字说明。恢复身份期间只显示页面外框与「正在确认登录状态」，不短暂露出管理员菜单。

## 2. 登录与修改密码

| 页面 | 从上到下的内容 | 提交后 |
|---|---|---|
| 登录 | 桌面左侧为品牌、引文与折光镜片，右侧为单列认证卡：标题「登录后台」、带标签的「登录名」「密码」、主按钮「登录」。没有注册、找回密码或公开初始化入口。 | 按钮显示「正在登录…」。成功后，有权访问原站内目标时返回该页，否则到首页。临时密码优先进入改密。认证失败统一显示「登录名或密码不正确」，保留登录名、清空密码；连接失败用另一条提示。 |
| 首次／重置后改密 | 不带侧栏。标题「设置新密码」，说明「你正在使用临时密码，修改后才能进入后台」。依次输入「当前密码」「新密码」「确认新密码」，操作为「修改密码」「退出登录」。 | 两次新密码不一致时定位到确认框。成功后清空表单，返回登录并显示「密码已修改，请使用新密码重新登录」。不能用返回键跳过。 |
| 主动改密 | 从账号菜单或个人首页进入。共用三项输入；「取消」可回首页。提交前说明「修改后，所有已登录的会话都需要重新登录」。 | 校验失败停在表单；成功后与首次改密相同。 |

密码输入默认遮蔽、允许粘贴。新建账号时，临时密码字段提示「15–128 个字符」；改密和重置再提示「新密码不能与当前密码相同」。登录页不显示设置新密码的规则。客户端不裁剪密码空格。任何页面都不在详情或成功消息里回显密码，不把密码保存到可恢复的草稿；退出表单或刷新后清空。

## 3. 用户管理：先建账号，再授权

列表页标题「用户管理」，右上角按权限显示「新建用户」。标题下是「登录名或显示名」搜索框、状态筛选（全部／启用／停用）和「查询」「重置」。表格列依次为**登录名、显示名、状态、角色、操作**；登录名链接到详情。行内常驻「查看」，其他允许的操作放在「更多」里。角色太多时显示前两项与剩余数，在详情查看全部。首次加载每页 20 条，可选 20／50／100；改变筛选回到第一页。

以下是管理员看到的用户列表，方括号代表可操作控件。只读账号的同一页去掉「新建用户」和「更多」，保留搜索与「查看」。

```text
用户管理                                         [新建用户]
[登录名或显示名]   [状态：全部]                   [查询] [重置]
登录名       显示名     状态     角色             操作
chenning     陈宁       启用     用户只读         [查看] [更多]
```

| 操作与载体 | 字段与反馈 |
|---|---|
| 查看、编辑（右侧面板） | 详情展示登录名、显示名、状态、已绑定角色；停用角色标「已停用，不生效」。编辑时仅显示名可改。普通维护者看到管理员账号只能查看。 |
| 新建用户（右侧面板） | 输入登录名、显示名、临时密码。表单注明「新用户默认启用，创建后暂未分配角色」，不混入角色选择器；提示操作者通过线下渠道把临时密码交给本人。成功后刷新列表，只有管理员看到「继续分配角色」。 |
| 分配角色（管理员面板） | 标题带目标登录名；列出可新增的启用角色，以及原有的停用绑定（可保留或移除，不可新加）。底部显示「将添加」「将移除」的角色，再一次性「保存分配」。无变更时不可提交；取消不改变绑定。 |
| 启用／停用（确认框） | 列出显示名及登录名。停用前说明「该用户所有会话将失效」；重新启用注明「需要重新登录」。确认按钮写「停用用户」或「启用用户」。自己的「停用」不出现。 |
| 重置他人密码（管理员确认框） | 标题点明目标，输入新的临时密码；提示「现有会话将退出，下次登录必须改密」。成功只提示「临时密码已重置」，不显示密码。普通维护者和目标本人均无此入口。 |

**授权示例：** 林青给 `chenning` 分配「用户只读」时，底部显示「将添加：用户只读；将移除：无」。只有本次新增 `ADMIN` 时才突出「将授予 chenning 后台管理员权限」，主动作改为「确认授予管理员权限」。从他人账号移除时改为「确认移除管理员权限」；原样保留时使用普通的「保存分配」。编辑自己的角色时，`ADMIN` 显示为已选且不可取消，并说明原因。若保存时触发最后一个管理员保护，应显示具体原因，不能提示保存成功。

## 4. 角色管理：看清权限和受影响的人

标题「角色管理」。筛选项为「角色名称或编码」及状态；列表列为**角色名称、编码、状态、绑定用户数、操作**，分页沿用用户列表。详情面板显示角色权限，并可查看固定权限目录。`ADMIN` 标「内置 · 只读」；详情说明它专有的分配角色、重置他人密码等能力，不显示编辑或启停。

- **新建／编辑自定义角色：** 输入名称、编码；编辑时编码只读。权限按「用户」「角色」分组，用可理解的名称如「查看用户」「维护普通用户」「查看角色」和简短说明。选择「维护普通用户」时，「查看用户」显示已包含，不能留下“能改不能读”的组合。权限可全不选，显示「该角色暂不提供管理权限」。管理员的专有操作不进入可勾选清单。
- **停用／重新启用：** 确认框同时显示角色名和当前绑定人数。示例：「停用『用户只读』？已绑定 3 个账号。绑定会保留，但该角色不再授予权限。」重新启用明确告知原绑定将重新生效。若用户另有角色提供相同权限，提示「其他启用角色授予的权限不受影响」。

## 5. 状态与恢复动作

| 触发情况 | 用户看到什么 | 下一步 |
|---|---|---|
| 首次读列表／提交中 | 显示「正在加载用户…」等明确状态；提交按钮变为「正在保存…」。 | 同一表单不重复提交，服务端确认后再刷新列表并告知成功。 |
| 成功返回零条 | 未筛选：「暂无用户／角色」，有创建权才提供新建；有筛选：「没有符合条件的记录」。 | 筛选空态提供「清除筛选」。请求失败不走空态。 |
| 输入有误（400）或重名（409） | 错误贴在对应字段旁，如「登录名已存在」；焦点移到首个错误字段。 | 保留非敏感输入，就地修改。 |
| 在受保护页面会话失效（401） | 清除受保护内容，返回登录，提示「登录状态已失效，请重新登录」。 | 登录后重新检查原站内目标的访问权限；主动退出后仅提示「已退出登录」。 |
| 权限不足或变更（403） | 会话保持登录。不能再读列表时立即清掉列表与已打开的详情；若只丢失编辑权，关闭编辑区，按仍有的读取权限重载。 | 显示「你已无权执行此操作」或「你没有访问此页面的权限」，重新读取有效权限与导航，提供「返回首页」。不要求用户退出重登。 |
| 数据已被他人修改（409） | 在面板中提示「数据已更新，请重新加载后确认」。状态保护冲突则说明实际约束，如「必须保留至少一名启用的管理员」。 | 版本冲突提供「重新加载」：读取最新值，再由用户重选和保存，不能自动覆盖；约束冲突读取最新状态后返回。 |
| 登录频率受限（429） | 登录表单提示「尝试次数过多，请稍后再试」。 | 保留登录名，清空密码；不自动重试或显示无依据的倒计时。 |
| 只读请求断网／服务不可用（503） | 内容区提示「暂时无法连接服务」，保留筛选，不显示零条或虚构成功。 | 提供「重试」；身份尚未确认时不展示管理内容。 |
| 写入后断网，结果未知 | 持续提示「暂时无法确认是否保存成功」。 | 用户或角色变更提供「查看最新记录」核对后再操作；密码不提供回看，可重新验证登录，重置他人密码由对方核对。界面不自动重发写请求。 |

## 6. 本期如何应用 UI 规范

配色、字号、间距、响应式和键盘操作见[内观 UI 设计规范](../../ui-design-guidelines.md)。本期用法如下：

| 页面 | 打开后的视觉重点 |
|---|---|
| 登录、首次／重置后改密 | 1280px 下为品牌与表单分栏，右侧卡宽 456px。左侧保留三片带孔的折光镜片；「向内，见深。」下放「知人者智，自知者明。」及出处《道德经》第三十三章，页脚解释中文名「内观」：内视自身，自省自身。卡片可透光，字段清楚可辨。主操作是「登录」或「修改密码」，强制改密另有「退出登录」；主动改密沿用后台实底表单。 |
| 后台首页 | 1280px 的后台顶栏高 72px，侧栏宽 196px。账号卡以镜片和少量玻璃反射表现身份信息；其下列出获准的入口。管理员有两张入口卡，仅有用户读取权时仅有「用户管理」；画板 16 没有管理权限，原位给出原因和改密入口。 |
| 用户管理、角色管理 | 两页共用「页标题与新建 → 筛选 → 表格 → 分页」。有创建权时「新建用户／新建角色」在页首，查询用描边按钮，重置用文字。名称链接和「查看」常显；只读账号不出现「更多」。窄屏保留对象名、状态和「查看」，其余字段及有权操作进入详情。 |
| 详情、授权与异常 | 在当前主题的不透明面板中对齐字段与值；授权面板把「将添加／将移除」放在提交按钮前，管理员权限变化按第 3 节明示。危险确认的初始焦点在「取消」。冲突提示和「重新加载」放在面板内；撤权优先清除无权内容，恢复动作按第 5 节执行。 |

**双主题是本地外观偏好。** 默认跟随操作系统，无法判断时用浅色。手选后只在当前浏览器记录 `innersight.theme`（`light` / `dark`）；登录、退出、刷新保持。若存储被禁用，仍可在当前页切换，重载后回到系统默认。切换不触发请求或导航，也不清除输入、报错、列表筛选和页码。

胶囊在个人信息左侧，登录与强制改密时保留右上角位置。桌面显示日／月与「浅色」「深色」，320px 下只显示图标，每段保留可读名称和至少 44×44px 的点击区。使用一组名为「界面主题」的原生 radio；Tab 入组与离组，方向键和空格选择，读屏可识别选中项。减少动态时停用视差与过渡。弹层锁住背景焦点；画板 14 是全屏详情，从详情返回后再切。

**设计入口。** Pixso [浅色总览](https://pixso.cn/app/design/NYBXHNEYrfdASgLhilojEg?page-id=6%3A198&item-id=6%3A199)、[深色总览](https://pixso.cn/app/design/NYBXHNEYrfdASgLhilojEg?page-id=6%3A2344&item-id=6%3A2345)各有 00–20，可编辑、按同号对照；[离线动效样例](04-motion-study.html)可实际体验登录与首页的切色、镜片动效和账号菜单。样例的「填入演示账号」仅用于看稿。编号对应如下：

| 画板 | 评审内容 |
|---|---|
| 00 / 01–03 | 总览；登录、强制改密、管理员首页 |
| 04–06 | 用户列表、角色列表、具备 `user:read` 的只读列表 |
| 07–12 | 新建用户、授予管理员、新建角色、停用角色影响、撤权、保存冲突 |
| 13–15 | 320px 的只读用户列表、全屏详情、登录失败 |
| 16–19 | 无管理权限的个人首页、主动改密、重置他人密码、内置角色详情 |
| 20 | 加载、无匹配、读取失败、保存结果未知、会话失效、登录受限 |

## 7. 设计走查与业务验收

打开两个独立浏览器会话，分别作为管理员林青和普通账号陈宁。这里列出未来能从界面观察的结果；数据库、会话撤销与并发写入的实际验证仍按 [PRD 验收用例](02-prd.md#acceptance) 执行。

| 走查顺序 | 观察点 | PRD 用例 |
|---|---|---|
| 启动、登录、首次改密 | 没有公开初始化入口；临时密码只能改密或退出；改密后需重新登录。 | AC-01、AC-02、AC-03 |
| 林青建角色、建用户、分配角色 | 用户先以「未分配」出现；授权前看到对象和权限变化。陈宁登录后只看到获准入口。 | AC-04、AC-05、AC-06 |
| 收回读取权，再停用账号 | 移除一个角色但仍有相同权限时继续可读；移除最后一份读取权后，陈宁再次打开或刷新用户列表时收到 403，列表清空，无需重新登录，仍能访问个人首页；账号被停用后，再访问首页也会回到登录页。 | AC-07、AC-02 |
| 模拟两个管理员同时更改同一对象 | 管理员保留规则有明确说明；后保存的一方看到冲突和重载入口，没有“覆盖保存”。 | AC-08、AC-09 |
| 筛选、翻页、断开服务 | 分清“查不到记录”“读失败”“写入结果未知”；列表分页，检查无权按钮、抽屉焦点和窄屏主要操作。 | AC-10、AC-11 |
