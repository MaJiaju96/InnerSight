## 1. 问题与交付边界

InnerSight 从空工程起步。第一位维护者要能启动应用，建立自己的管理员账号，给另一个人开通后台账号，并可靠地控制对方能看什么、能改什么。后续题库等功能可以使用同一个登录身份，本期只定义后台现有资源的权限。

| 本期交付 | 留给后续独立需求 |
|---|---|
| Vue + TypeScript 前端、Spring Boot 模块化单体、MariaDB Server 10.11.19 主库；可复现的初始化、真实联通和故障提示 | 题库、面试、报告、模型接入，以及这些业务的数据归属与授权 |
| 一个应用内的账号登录和会话、后台首页、用户管理、角色管理、固定权限目录及授权 | 公开注册、短信/第三方登录、部门、团队、多租户、自定义权限表达式、通用菜单设计器 |

以下规则已与本期 PRD 一并确认。数据库选型见[技术方案书](../../02-technical-design.md)；表结构和 API 路径由工程设计确定。

## 2. 使用者与授权规则

同一账号可以绑定多个角色，有效权限是所有**启用角色**权限的并集。启用账号即使没有角色，也能进入个人首页、修改自己的密码并退出。匿名用户只能访问登录入口及必要的公开就绪状态。角色停用不删除绑定，但不再贡献权限。

| 能力 | 内置管理员 `ADMIN` | 自定义角色能否获得 |
|---|---|---|
| 当前账号首页、改自己的密码、退出 | 可以 | 所有正常登录账号都有，不用授权 |
| `user:read` 查看用户列表和详情 | 可以 | 可授予；只展示账户资料、角色名和状态，不展示密码信息 |
| `user:manage` 新建无角色账号、编辑普通用户资料、启停普通用户 | 可以 | 可授予，同时包含 `user:read`；不能用来改角色绑定、重置他人密码或维护管理员账号 |
| `role:read` 查看角色列表、详情和权限目录 | 可以 | 可授予；目录是随应用发布的只读清单 |
| 新建、编辑、启停自定义角色；分配用户角色（含 `ADMIN`）；重置他人密码、维护管理员账号 | 可以，仍受管理员保留规则约束 | 不可授予；这几项只由内置管理员执行 |

普通用户指未绑定 `ADMIN` 的账号。`ADMIN` 角色不可编辑、停用或删除。自定义角色从固定权限中勾选，不接受未登记的权限项。首版不提供用户或角色的硬删除；停用后保留管理记录。

## 3. 功能需求

| 编号 | 能力 | 规则与成功条件 |
|---|---|---|
| FR-01 | 工程与初始化 | 提供实际的版本、环境示例、数据库初始化与启动说明。没有模型配置也能启动。空库经显式本地初始化创建首个启用的 `ADMIN` 账号；初始凭据由部署者提供，无内置通用密码、无公开初始化入口。重复或并发执行只产生一份初始化数据，不重置已有密码。开发和测试使用独立的 MariaDB Server 10.11.19 数据库及账号。真实库验收以服务端返回的产品、补丁版本与测试库名为准。 |
| FR-02 | 登录、退出与会话 | 只允许启用账号登录。账号不存在、停用或密码错误返回同一失败提示；服务不可用单独提示。默认：同一来源与规范化登录名组合在滚动 10 分钟内连续失败 5 次，随后限流 10 分钟；认证成功清零，限流期间重试不延长窗口。无活动 30 分钟或登录满 8 小时需重新认证。退出使当前会话服务端失效；停用账号使其全部会话失效，重新启用不能恢复旧会话。 |
| FR-03 | 初始密码与改密 | 初始化、新建用户及管理员重置密码时，操作者设置临时密码，线下交给本人；表单提交后不可再查看。使用临时密码首次登录只允许改自己的密码和退出。改密需验证当前密码，新密码为 15–128 个字符且不同于当前密码，可粘贴；按原文验证，不裁剪空格。设置临时密码也遵守相同长度要求；重置时不得复用当前密码。改密或重置后撤销该账号全部旧会话，须用新密码重新登录。 |
| FR-04 | 用户管理 | 登录名去首尾空白，忽略大小写唯一；3–32 个英文字母、数字、点、下划线或连字符，创建后不可改。显示名去首尾空白后 1–50 个字符。新建默认启用且无角色；分配角色是另外的管理员操作。支持按登录名/显示名搜索、按状态筛选、分页、查看详情、改显示名、启用和停用。管理员可重置他人密码；自己走改密流程。 |
| FR-05 | 角色与权限目录 | 创建、编辑、启停自定义角色；支持按名称或编码搜索、按状态筛选、分页和查看详情。角色编码 3–32 位英文字母、数字或下划线，忽略大小写唯一，创建后不可改；名称去首尾空白后 1–50 个字符，权限可为空。停用/重新启用前显示绑定用户数；重新启用时，原有绑定重新贡献权限。 |
| FR-06 | 分配与执行权限 | 仅 `ADMIN` 能为用户分配角色。可新增绑定启用角色，可保留或移除原有的停用角色绑定。整个选择一次保存。管理员为他人操作时，也须在写入时检查操作者仍有权限、目标仍可维护。后台逐次校验账号、角色和操作权限；变更成功后的下一次受保护请求即按新权限处理。未认证返回 401，已登录但无权返回 403；页面是否显示按钮不参与后端判定。 |
| FR-07 | 并发写入与管理员保留 | 不能停用自己或移除自己的 `ADMIN`。系统始终至少保留一个启用且绑定 `ADMIN` 的账号。并发停用、卸任或重复授权也必须满足此条件。用户资料、用户角色集合、角色权限集合拒绝基于旧版本的覆盖写入，冲突时要求重载并重新确认；一次变更要么全部提交、要么全部回滚。 |

## 4. 质量要求

| 编号 | 约束 | 交付时应提供的证据 |
|---|---|---|
| NFR-01 | 身份与凭据 | 密码在服务端以专用加盐密码散列保存。生产通过 HTTPS 传送凭据；采用可撤销的服务端会话，会话 Cookie 设为 HttpOnly，生产设为 Secure，限制跨站发送。服务端对写操作校验跨站请求；前端持久存储、URL、日志、响应及仓库示例中无密码、可复用会话凭据或真实密钥（设置会话的 Cookie 除外）。未明确授权的服务端操作默认拒绝。 | 验证会话撤销、Cookie 保护属性、越权拒绝、敏感字段及日志脱敏。 |
| NFR-02 | 并发与一致性 | 初始化、名称唯一性、授权和管理员保留规则由服务端保障；不能靠按钮防重。相互冲突的管理写入按有效授权和数据版本提交；失败不留下部分绑定。 | 使用独立会话触发竞争写，核对响应和最终数据库状态。 |
| NFR-03 | 稳定性与追溯 | 区分未登录、权限不足、冲突和服务不可用。就绪状态反映数据库是否可用，对外不暴露连接串或调用栈。成功的用户、角色和授权变更可追溯操作者、对象、动作、时间及结果；认证失败可排查，不记录密码。无需建设审计查询页面。 | 断开并恢复测试库、重启应用；验证失败不报成功、数据保留、日志可定位。 |
| NFR-04 | 列表性能 | 用户与角色列表默认每页 20 条、最多 100 条，排序稳定；首版按创建时间倒序、同时间按唯一标识倒序。后端分页，不逐个用户额外查询角色。 | 在测试库用 1,000 个用户、20 个角色检查筛选、翻页、查询次数；记录环境、查询次数及耗时基线。此数据量是验证样本，不是容量承诺。 |

## 5. 与实现的交接

业务只依赖当前身份和已授予权限；登录、授权及基础管理与以后的训练模块分开。在开始开发前确定实际工具链、数据库迁移方式与测试命令，写入启动说明。各规则的场景验收见 [PRD 第 4 节](02-prd.md#acceptance)；代码自审与发布遵守[项目开发约束](../../../AGENTS.md)。
